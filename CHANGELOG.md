# Changelog

This file lists every notable change to fffinder. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Quoted words in a name search, such as `"tax exemption"`, match only names that have them as written, letters in a row. Unquoted words still match fuzzily along the path inside the search location, or inside the folder when only one is searched, so `taxexemptionc` also finds `tax/exemption/coding/Handler.java`, whose folders spell it out in order.
- An **Allow typos** switch in Settings › Search engine. Turned off, a name search never shows typo-tolerant matches, even when nothing else matches. It's on by default, as before.
- `--here` searches only in the folder a command opens. `fffinder ~/src --query readme --here` starts the window with **Search Only in "Folder name"** on, so the search, and anything typed later, covers `~/src` and everything inside it instead of every search location. It works without `--query`, in a `--pick` chooser, and when a running fffinder takes over the launch. In Nushell, `fff gui`, `fff pick`, `fff insert`, `fff cd`, and `fff edit` take `--here`, and `fff keybindings --here` makes Ctrl+T and Alt+C pick from the current folder and below. `POST /v1/open` takes `"in_folder": true` for the same. Before, a folder given with a search was only where the window opened: `fff gui ~/src --query readme`, the module's own example of searching under a folder, searched every location, and a chooser opened in a folder outside the search locations found nothing in it. When the fffinder that the Nushell module finds is older than the module and refuses an option, `fff pick` and the commands built on it now fail with its message, such as "unknown option: --here", where they returned nothing as if the chooser had been cancelled.
- Right-click the Back or Forward button for a menu of the places it leads to, nearest first, and choose one to go straight there instead of a step at a time. The menu lists up to twelve places, and a folder with the same name as another place in it shows the folder it is in, as in "src — atlas". Each button's tooltip names the place a click leads to, such as Back to "Projects".
- Click an example in the Search Syntax table (Cmd+/) to try it. The example goes into the search field in place of what was there and is searched for right away, by name even if Contents was on. Undo in the search field (Cmd+Z) brings back what it replaced. The table stays open so you can try one after another, and it highlights the row of the example that's being searched for. Its first row says whether typos are allowed, as **Allow typos** is set.
- The preview of a contents search result opens at the matching line. A text or code preview used to show such a file from its first line, in the Preview Pane, the gallery, and Quick Look, and you had to find the line the list names by eye. It now opens at that line, with up to two lines before it in view and the rest of the file a scroll away. The line is highlighted and drawn in the plain text color, so that it reads on the highlight. When the match is further into a file than the first 64 KB a preview reads, the preview opens at its end, where "preview truncated" says which line the match is on. A file that has changed since the search, so that the line reads differently, opens at its top with nothing highlighted. Markdown previews stay rendered and open at the top.
- Cmd+Return shows the selected item in its enclosing folder: the folder opens in the window with the item selected, and Back returns to where you were. It works on one selected item in search results, Recents, and results sent from Nushell, so a search can go from its words to a result's folder without the mouse: type, press Return to move into the results, then Cmd+Return. The item menu shows the shortcut beside Show in Enclosing Folder, and the toolbar's Actions menu has the command too in those lists. It does nothing in a folder or in the Trash.
- Settings › Nushell can choose which `nu` fffinder uses. **Choose…** picks it with the file chooser and saves it as `nu_path`; **Find Automatically** goes back to looking on `PATH` and in the usual install folders, and **Look Again** looks once more when none was found, for a `nu` installed while fffinder is running. The choice is used at once in every tab and window, with no restart: Nushell actions, filters, previews, Quick Look's explore mode, and Nushell's file colors are read again with it. The line beside the buttons names the `nu` in use, and says so when the chosen file isn't there and another one is used instead. Before, the messages for a missing `nu` said to set its path in Settings, which had no control for it: the path had to be typed into settings.json, followed by a restart. A `nu_path` edited into settings.json by hand now also applies when the next tab or window opens. This helps most when fffinder is opened from the Dock or a desktop menu and `nu` was installed with nix, mise, or asdf, which such an app can't find on its own.
- Tabs take more from the mouse. Drop items on another tab to move them into the folder it shows, or to copy them, by the same rules as a drop on a folder; files from other apps are copied in. Middle-click a tab to close it. A tab's right-click menu has Close Other Tabs, which leaves only that tab. And a tab being dragged shows its name under the mouse. A double middle-click on a folder now opens that folder alone, where its second click also opened the folder under the pointer in the new tab.

### Changed

- Globs in a name search follow the letter case setting, now called **Letter case in searches**. Before, `*taxex*` never found `TaxExemption.object`, even with case set to ignore.
- Tooltips show the keyboard shortcut of what their button does: Back, Forward, the four view buttons, Show Sidebar and Hide Sidebar, Filter with Nushell and Search Syntax in the scope bar, the close buttons of the filter bar and the Nushell panel, and the sidebar's Settings button. The tab bar's + has a tooltip, New Tab, and the × of the tab that is showing names Cmd+W. Back, Forward, Enclosing Folder, and Move to Trash have Finder's shortcut and the one Explorer and the Linux file managers use; menus and tooltips show Finder's on macOS and the other on Linux and Windows. On macOS that corrects the item menu and the Actions menu, which showed a bare ⌫ for Move to Trash instead of Cmd+Backspace, and Go › Enclosing Folder in the menu bar, which showed Alt+Up instead of Cmd+Up.
- Escape in a search field that is already empty gives the keyboard back to the files, so the arrow keys, Space, and typing to select work again without a click. With words in the field, Escape still empties it and ends the search, and the keyboard stays in the field for other words. The Nushell filter's field does the same: Escape empties it, and in an empty field Escape gives the keyboard to the files and leaves the filter bar open. In a `--pick` chooser, where Escape in the files cancels, pressing Escape over and over in the search field now ends in Cancel. It used to stop at the empty field.
- Back and Forward now remember searches. Going somewhere else from a search, by opening a folder from the results, Show in Enclosing Folder, a folder or place clicked in the sidebar or the path bar, Go to Folder or Enclosing Folder, keeps the search in the window's history, and Back returns to it: the same words, in This Computer or the folder, by Name or Contents, with the folder you came back from selected if it is one of the results. Search Only in This Folder is then on or off as that search had it. Back during a search now only ends the search and stays in its folder, where it used to go on to the place before as well, and Forward brings the search back. So from a folder opened from the results, Back leads to the results, then to the folder you searched from, then to the place before it. The Back button is enabled during a search even in a window that has been nowhere else, the Back and Forward menus list a search as Searching "text", and the tooltips name it, both with long words cut short. Forward with nowhere to go no longer ends a search. A search that comes back runs again with the kind and the Nushell filter chosen now, in relevance order; a Smart Folder's search comes back with its own kind and filter. One ended with Escape or by emptying the search field is not kept.
- Smart Folders are easier to save, and opening one no longer changes how you search afterwards. **Save** is now in the scope bar of every search (it was in the Nushell filter bar), Cmd+S does the same, and **Save Search…** is in the Actions and Edit menus. The dialog says everything it saves: the words, Name or Contents, the folder or This Computer, the kind, and the filter. When a Smart Folder already has the name you type, the dialog says that saving replaces it, its button reads Replace, and the replaced one keeps its place in the sidebar. A Smart Folder's kind, scope, Name or Contents, and filter now last as long as its search. When you go elsewhere, press Escape, or empty the search field, the window searches the way it did before and its own filter is back. Before, a folder opened after a Smart Folder stayed filtered, and the Smart Folder's kind became the kind of new tabs and of the next launch. What you change by hand while a Smart Folder is open stays. If you used a Smart Folder to load a filter and then browsed folders with it, type that filter in the filter bar instead. Back and Forward return to a Smart Folder's search with its kind and filter. A Smart Folder's row is highlighted only while its whole search is showing, so two with the same words no longer light up together, and one whose folder is gone says that it is searching This Computer instead.
- Search results and Recents follow files that other programs add, remove, or rename, as open folders already did. A search by name, a Smart Folder's too, runs again by itself a few seconds after a file it lists, or could list, comes or goes. What's selected stays selected, and results the file made no difference to are left as they are. Recents is read again when a file it would show is added, removed, renamed, or written to, though not for writes to the file it has first already, which keeps the size and date it showed until Recents is next read. A search by contents still waits for Refresh (Cmd+R), and with Watch folders for changes off everything waits for Rescan.
- Search results that match equally well are listed newest first, by when they were last modified, and then by path, so a search for `screenshot` or `invoice` starts with the latest files whichever search location they are in. They used to come one search location after another, and in no order inside one when there were many. A search made again now lists the same items in the same order, where a list of many equally good matches could change from one search to the next, and with Any Kind the most recently modified of a few thousand equal matches could be the ones left out; only a search with thousands more equal matches in one search location than it ranks can still vary. A one-letter search of a search location with more than 20,000 files lists folders as well, where it could list files alone. Several words that spell a whole name rank it as an exact match, so `tax return` lists `Tax Return.pdf` ahead of `Tax Return 2024.pdf`.
- With **Allow typos** on, a name search that nothing matches without typos now lists only near misses. It used to list everything fff-search's own typo matching returned, which lets a word go without two of its letters or more and takes the rest from anywhere along the path, so `bduget` listed `debug-test.log` beside `budget.txt`, and `xqz` listed every name with an x, a q, or a z. A near miss has the word in one place with one typo: a letter that is wrong, missing, or one too many, or two letters side by side that have changed places. A word of eight letters or more can have two typos, and a word of three letters or fewer none. Searching one folder for a word that is in the folder's own name no longer lists everything in the folder. Some searches that found their item among those results now find nothing: a typo together with gaps (`prjatlz` for `Project Atlas.txt`), two typos in a word shorter than eight letters, and a typo in a word of three letters or fewer. A single letter from A to Z, digit, or symbol beside a longer word no longer narrows a search to the paths that have it somewhere: `a budget` finds every budget, and `photo 2` finds every photo, with `photo 2.jpg` ahead of the others. `fff find` follows the same rules.

### Fixed

- Return or Down Arrow pressed in the search field before the results were in acted on what the window still showed. The first item of the folder, or of an earlier search, was selected and then lost when the results arrived, and a quick second Return opened it. Both keys now wait for the results, and for a Nushell filter still running over them, and then move in with the first result selected. Typing on or moving the caret calls that off, and when nothing is found the keyboard stays in the search field. Return also no longer runs a search again when its results are already in, or starts over one that is still running, which made a slow contents search take longer. Refresh (Cmd+R) still runs it again.
- A capital letter in a search word made the word match letter case exactly, so `README` never found `readme.md`, `TODO` never found `todo.txt`, and `NOTES` never found a folder named `Notes`. Unquoted words now ignore letter case however they are typed, as the manual says. A capital is a preference: names that fit the capitals still rank higher, so `README.md` comes ahead of `readme.md` and initials such as `TEC` still bring up `TaxExemptionController.java`. Typing an app's name with its capital, as in `Safari`, no longer lists a file or folder of that name ahead of the app. A search also remembers the file you opened from it whatever the letter case, and when it has quoted words. Quoted words follow **Letter case in searches**. `fff find`, `fff files`, and `fff dirs` match the same way.
- After a search found nothing, every further letter flashed placeholder bars in place of "No Results" until the next answer came, and "Indexing…" blinked the same way while the index was being built. The message now stays where it is while the search runs again; a contents search, which can take seconds, reads "Searching…" meanwhile. A search also no longer shows items that aren't its results while it waits for them: the folder's items after the first letter, or names under the Match header and matching lines under Folder after a switch between Name and Contents. Placeholders show until the results are in. The first search of a folder outside the search locations says "Indexing…" while its index is built, where it said "No Results".
- A content search went on after you typed on, changed where it looked, cleared the search field, or closed its tab, until it had filled its results or reached the time limit. Several ran at once and slowed down the one you were waiting for, and with the time limit set to None they could read every file. A content search now stops as soon as the search changes or ends. Reading the file counts for the sidebar also no longer runs on the window's thread, where it could freeze the window while a content search or a scan was under way.
- A text, code, font, or table preview could open scrolled to where the previous file's preview was left. After scrolling down in one source file, going back to a file you had already looked at showed it from that place instead of from its first line. It happened in the gallery, the column view, the Preview Pane, and Quick Look. Each file's preview now starts at its top (a contents search result's at its matching line), and a table that is wider than its space starts at its left edge.
- A name search of This Computer looked for its words in the whole path of each result, including the search location's own path, which is never matched. A word whose letters are in that path, such as `users` under `/Users/alice`, counted as found in every result, and so did the first letters of any other word: under `/home/user`, `music` needed only an `i` and a `c` from the rest of the path. Matches that fff-search only made by leaving letters out then stayed in the list beside the real matches, so `music` also listed `basic.txt`. Words are now looked for only in the path inside the search location, as the manual says and as searching one folder already did. `fff find` follows the same rule.
- Search results opened wherever the folder had been scrolled to, or at the end of a shorter list, with the best matches out of view, and they stayed scrolled when you typed on. Results now start at the top with nothing selected whenever the words, the scope, the kind, or Name and Contents change, so Down Arrow and Return in the search field go to the first result and not on from one selected earlier. A search that only runs again, as with Refresh, keeps its selection and stays where it was scrolled to. Ending a search with Escape or by emptying the search field puts the window back as it was before the search: the same items are selected, and the view is scrolled to the same place.
- A click on This Computer, the folder's name, Name, or Contents in the search scope bar took the keyboard away from the search field, or from the files, and gave it to nothing: letters typed next were lost, and the arrow keys did nothing, until you clicked the field or a file or pressed Cmd+F. The keyboard now stays where it was, so you can switch to Contents and go on typing, or press Down Arrow to move into the results. It stays in the filter field the same way. Search Syntax opened with the bar's (i) button gives the keyboard back to the search field when it closes, and a Return or Down Arrow that is waiting for the results still moves into them after a click in the bar. When nothing had the keyboard, the click gives it to the files, and in split view a click in the other pane's scope bar gives it to that pane's files.
- A content search for a common word listed far fewer files than **Results shown** allows, about 100 of 500, with no sign that more matched, because it counted every matching line toward the limit. It now lists up to that many files. The `+` after the item count is no longer a guess from the length of the list: a search that finds just as many items as the limit has none, and a search whose best matches include hidden files that aren't shown no longer comes up short without one. Rest the mouse on a count with a `+` to read what to do about it. The content search time limit now covers the whole search instead of each search location in turn, so searching three locations no longer takes up to three times the limit, in the window and for `fff search`. A content search that reaches the time limit with nothing found says "Nothing Found Before the Time Limit" instead of "No Results".
- Folder filters didn't filter in the searches most people run. With **Any Kind**, the kind a search starts with, and with **Folder**, `/notes/ todo` and `todo notes/` took the folder for one more fuzzy word, so they also listed `meeting-notes/todo.txt` and `other/notes-todo.txt`. Only a search for one kind of file, such as Document, kept to the folder. A folder filter beside other words now keeps to what is inside a folder with exactly that name, whatever the kind. The name must match whole, with letter case ignored from A to Z. `!notes/` leaves out only what is inside a folder named `notes`; it used to leave out every path with `notes/` in it, `meeting-notes/` included. Two of them at the end, as in `readme projects/ !atlas/`, no longer turn the results into folders only. A folder filter that is the whole search, such as `src/`, still lists the folders that match it, and globs work as before. `fff find` follows the same rules.
- The **Kind** menu missed files. **Document** never found a presentation (`.pptx`, `.ppt`, `.key`), and **Code**, **Archive** and **Document** left out extensions that fffinder shows with their icons, such as `.htm`, `.bat`, `.proto`, `.crate`, `.log` and `.jsonl`. Each kind now goes by one list of extensions. An extension typed in the search was ignored once a kind was chosen: with **Image**, `logo *.svg` listed every image named logo. It now narrows the kind, so that search lists only the SVG images, and `logo *.txt` lists nothing, in a Smart Folder saved that way too. `fff find --kind` and `fff open` follow the same rules. A name with no extension, such as `README`, is still found only with **Any Kind**.
- Sorting search results only reordered the items already listed, so with more matches than **Results shown** the largest or newest ones could be missing: `*.log` by Size gave the largest of an arbitrary 500. When a search finds more than it lists, a sort now chooses among every match, up to 20,000 in each search location. For unquoted words, which match loosely, it chooses among the items that have every word in their name, when the list holds nothing else and more of them match than fit; otherwise the list stays the best matches, in the new order. In search results the Date Created and Date Last Opened columns were blank, Permissions said `read-write` for every file, sorting by Date Created sorted by name, and groups by either date put everything under No Date. They now show what the files have, read from the disk for the items listed while a column, the sort, or the groups use them. A search made from Recents is now sorted when you choose Name.
- With Quick Look open, Return in the search field sometimes selected the first result but left the keyboard in the search field, and Quick Look then ignored Escape, Space, and the arrow keys until it was clicked. Return after editing a name in place could leave the arrow keys and the other file keys doing nothing until a click. All of it happened when Quick Look's window was the last of the two to redraw before the key. Return now acts in the window it was pressed in.
- On macOS, the menu bar shows Cmd+R for View › Refresh, Cmd+O for File › Open, and Cmd+Y for File › Quick Look, where it showed F5, Return, and Space. The item menu shows Cmd+O for Open there too, instead of Return. In the file views Return, Cmd+Down, Space, and F5 do what they did, and nothing changes on Linux or Windows.
- **Search Only in "Folder name"** gave wrong or missing results in a folder whose path has a space, a bracket, a brace, `*`, `?`, or `!` in it, such as `Tax Returns` or `photos[2024]`. A contents search there could say No Results while files in the folder matched, once enough newer files elsewhere had the word, and found nothing at all in a folder such as `drafts[old]`. A name search could miss the folder's items when more than 20,000 others matched better. On macOS and Linux, a folder with a backslash in its name could not be searched at all. A search of one folder now looks only at what is in that folder, whatever it is called. A contents search of a folder that finds nothing also no longer goes on to read the rest of the search location, which could take it to nearly twice the time limit, and it finds text that reads like a filter, such as `!important`, `*.rs`, or `src/`, as a search of This Computer does. A folder name typed alone, such as `src/`, lists only folders in a search of one folder too, and a file opened from such a search ranks higher the next time. `fff find` and `fff search` with `--scope` or `--here` follow the same rules; with `fff find --files`, a folder name alone is a word in a folder as it is elsewhere.
- Back and Forward in the toolbar are dimmed while they have nowhere to go, and Search Only in This Folder is dimmed in Recents, the Trash, and other places that aren't one folder. They were drawn like buttons that can be pressed, so a new window showed a Back and a Forward that looked ready to use.
- A table preview scrolls down. The preview of a zip or tar archive, and of a database or another file opened with Nushell, showed only the rows that fit in its space, such as the first eight of an archive's items in the Preview Pane, and the others couldn't be reached, while the line under the table counted them all. The table now scrolls down to its last row in the gallery, the column view, the Preview Pane, and Quick Look, and still scrolls sideways when it is wider than its space. In the column view, the wheel over such a table scrolls the table, where it used to move the columns sideways.
- The file area's message said the wrong thing when a filter or a search setting left nothing to list. A folder or a search whose items a Nushell filter all hides now reads "No Items Pass the Filter", with how many items the filter hides and a **Remove Filter** button, where it read "This folder is empty." or "No Results". While the filter is still running, placeholders show instead of a flash of "This folder is empty." "No Results" now says what limited the search, as in "The search looked only in “Projects”, and only for items of the kind Image.", with **Search This Computer** and **Search Any Kind** buttons that search again without that limit. For a contents search it no longer suggests another kind, and says that files over the size set in Settings › Search engine aren't looked inside. A search that stopped at the result limit with nothing it could list reads "The Search Was Cut Short" instead of "No Results". The Kind menu's button is in the accent color while a kind other than Any Kind narrows the search. In a narrow pane the message keeps clear of the edges.
- The keyboard no longer goes dead when the part of the window that has it goes away. With the sidebar as a folder tree, a click on a row gives the tree the keyboard, and hiding the sidebar then, or switching it to a list, left every key doing nothing until something was clicked: not even Cmd+Alt+S brought the sidebar back. The same happened when a menu's item or button went from under it, as after Cmd+1 with a file's right-click menu open, and when Back or another shortcut left the folder while a name was being edited. The files now get the keyboard. A click on something that takes no keys doesn't take the keyboard away either. After a click on a row of the sidebar's list, the path bar, the status bar, or the empty part of a bar, the arrow keys and typing did nothing until a file or a field was clicked. The keyboard now stays where it was, in the files or in the search field, and a right-click or middle-click there leaves it alone too. In split view, such a click in the pane that doesn't have the keyboard gives it to that pane's files.
- With more tabs than fit, the last tabs and the + button ran off the right edge of the window, or under the second pane in split view, where the mouse couldn't reach them. The tab bar now scrolls sideways: turn the mouse wheel or swipe over the tabs to see the rest. A tab you open or switch to scrolls into view, the tab that shows stays in view when the window changes size or split view is turned on, and + stays at the end of the bar. A tab's right-click menu closes when the window changes size, where it used to go out of sight and come back later with only a click to close it.
- Collapsing every group of a list or icon view no longer replaces the view with "No Items. This folder is empty." The headers stay, each with its count, so a group can be opened again with a click. The same goes for a folder that opens with all of its groups already collapsed, since a tab remembers collapsed groups from folder to folder, and for search results, Recents, and the Trash, which read "No Results", "No Recent Files", and "The Trash Is Empty" with items in them. An empty folder now has the empty-space menu: right-click anywhere in it for New Folder, Paste, Show Hidden Files, and the rest, where a right-click did nothing. So has the file area under its other messages, such as "No Results", except the ones about a folder or a Trash that can't be read. A right-click on empty space now also opens its menu at the exact point where an item's menu was last opened, once the item has gone from there or its folder has been opened with the pointer at rest, where the first such click opened nothing. In the Trash, **Empty…** and Empty Trash… are no longer dimmed while a filter or collapsed groups hide every item. Results sent from Nushell whose items have all been moved or deleted say that the items can no longer be found, where they said "This folder is empty."
- A preview no longer goes on showing a file as it was before it changed. When another program saved a file, the list showed its new size and date a couple of seconds later, while the Preview Pane, the column view's preview, the gallery, and Quick Look kept the old contents beside them. A preview is now read again when its item comes back with another size or date: when its folder is read again, when a search runs again, and when Recents is read again. The old preview stays until the new one is ready, and text stays where you were reading it. An image is the exception: its place is empty while it is read again, and a preview drawn from the system's thumbnail shows the icon meanwhile. Quick Look opens a changed PDF again at its first page, and its explore mode a changed file from its top level. Refresh (Cmd+R) and switching between light and dark no longer leave the Preview Pane, the column view's preview, and Quick Look on a spinner until you select another item. A file written over in place, which changes nothing about its folder, still shows as it was until you refresh.
- A double-click on a dialog's Done or Cancel button, on its close button, or beside the dialog no longer opens the file that was under the pointer. The first click closed the dialog, and the second landed on the files as a double-click. A double-click on a menu item, on a notification's close button, or on the close button of a tab did the same, and over empty space the second click cleared the selection. An item now opens only when both clicks are on it. After a click on another item the second click only selects, and after a click on something that the click took away it does nothing to the files and leaves the keyboard where it was. Clicking on quickly after opening a folder no longer opens what comes under the pointer with every click: each item takes a double-click of its own.
- The column view lost track of what was selected. A column after the first remembered its selected item by position, so when its folder changed on disk, or on Refresh, Show Hidden Files or Keep Folders on Top, the highlight moved to a neighbouring item, and Open, Rename, Quick Look and Move to Trash acted on that one. A column now keeps its item selected wherever the item is listed, and when the item is gone, the columns to its right close. A renamed item stays selected, and in a further column shows its new name at once. After Back or Enclosing Folder the folder you came from is selected, and Show in Enclosing Folder selects the item, as in the other views. What a paste, New Folder, New File, Duplicate or Undo brings is selected when it lands in the column you're in, and Move to Trash selects the next item in the first column too. Sort By and Ascending or Descending now sort every column, not only the first. Escape clears the selection in the column view as it does in the others: the active column's item, which closes the columns to its right.
- New Folder left the keyboard in a name field that was never drawn when the list or icon view was in groups and the new folder's group was collapsed, or when a Nushell filter left the new folder out. After that the files took no key, and a click on an item selected nothing. The group now opens for the new folder, and under a filter the folder shows for as long as its name is being edited, then is filtered like any other item. An item being renamed also keeps its row when the filter answers again in the middle of the edit, where the edit used to end with half a name. The status bar now counts the items of collapsed groups too: it read "7 items" under headers that counted sixteen, and "N of M items pass the filter" left out the items that pass in collapsed groups.
- Browsing a folder of photos no longer fills memory. The icon view, the gallery strip, and Get Info loaded every PNG, JPEG, GIF, WebP, BMP, ICO, and TIFF image of up to 40 MB whole and kept it for as long as fffinder ran, about 48 MB for a 12-megapixel photo. They now show a thumbnail that fffinder scales down itself, the same on every system, and keeps with the system's thumbnails in the data folder. The large previews in the gallery, the column view, the preview pane, and Quick Look kept every image they loaded, and now keep the last three each tab or pane showed; a format the system draws, such as HEIC, is shown from its thumbnail as before. An image that was saved again now shows as it is once its folder is read again, as Refresh does, where it kept its old picture until fffinder was restarted. An item also shows its icon while its thumbnail is being made, where its place stayed empty, and an image that can't be read shows its icon with the extension badge.
- After going to another place, the items of the place the window left could still be selected, opened, dragged and dropped on until the new place had been read, under the new place's name and rules. That lasted up to a minute for Recents while the index was being built, and as long as it took for a folder on a slow network volume: an item of the Trash could be opened from Recents, and a folder's items had the Trash's menu, with Delete Immediately…. Those items now only show, for a sixth of a second at most, and then placeholders take their place until the new place has been read. A folder on a local disk still opens without the file area going empty in between.
- A Nushell filter kept its answer for an item after the item had changed. A file that another program saved stayed hidden when it had grown past `size > 10kb`, and stayed listed, and counted in the status bar, when it had shrunk under it. In a folder opened with a filter already on, the folders were judged before their sizes were known, so `size > 100mb` listed none of them, and a comparison joined to another condition, such as `kind == Folder and size > 1mb`, left a Nushell error over an unfiltered list. Refresh (Cmd+R) changed none of it. A filter now runs again when an item comes back with another size or date, and Refresh runs it again in any case, as a filter that goes by the time of day needs.
- **Search Only in "Folder name"** found nothing in a folder that the window had reached by anything but its plain path: with `..` in the path, as after `fffinder ../lib` on macOS and Linux or Go to Folder with `..`; through a symbolic link inside a search location, while **Follow symbolic links** is off, as it is at first; or, on macOS and Windows, by a path typed in another letter case than the folder's, such as `~/documents`. The window showed the folder's items, and every search of it said No Results. Such a folder is now searched where it really is, and the results show that place. A linked folder that leads outside the search locations gets a temporary index, like any folder there. `--here`, `fff find` and `fff search` with `--scope` or `--here`, and `scope` in `/v1/find` and `/v1/search` follow the same rule.
- Ending a rename with a click or a right-click on another item selected the renamed item again a moment later. The menu that the right-click had opened then acted on the renamed item, not on the item it named, so its Move to Trash moved the file just renamed to the Trash, and after a click the next key did the same. A name edited in the sidebar's tree and ended on a file did this with the folder, and so did a folder renamed among a search's results when the click was on a result inside it. The item pressed now stays selected, an arrow key pressed right after Return is no longer undone, and renaming a folder in the sidebar's tree no longer takes the selection from the items selected among the files. A press on an item inside the folder that is being renamed, in the list with that folder open in place or in the column to its right, still leaves the folder selected, not the item.
- A name with accented letters is found however it stores them. A name can keep a letter such as `é` as one character or as the letter followed by its accent, which is how macOS stores the names made in Finder and in most apps, and a search typed one way didn't match a name stored the other. `señor` could miss `señor.txt`, or list it only among loose typo matches without a highlight, and never found an app whose name is stored the other way. Both spellings now match and rank alike, with the word highlighted, in words, quoted words and folder filters, and Korean names stored as the parts of their syllables are found the same way. A word typed without accents finds the names that have them, after the names that have the word as typed and among those that have its letters with gaps: `resume` finds `Résumé.pdf`, which it did only for names stored the macOS way. For a name that stores each accent in one character with its letter, that works for up to two accented letters in a word, and in a large folder such a name can be left out when many others match the word loosely. A word typed with an accent is taken as typed, so `résumé` doesn't find `resume.pdf`, and quoted words are compared letter for letter. What a search opened is remembered for names with accented letters too. `fff find` matches the same way.
- With **Allow typos** on, a misspelled word now finds the name that was meant in a folder of any size. Near misses used to be listed only when nothing at all had the word's letters in order, and in a large folder some long path has them by accident, spread over its folders and its name. The name that was meant was then left out and the accidents were listed: among the sources of some nine hundred Rust crates, `benchmrak` found two files that have nothing to do with benchmarks and no `benchmark.rs`. Near misses of a word are now listed whenever no result has the word as typed, with its letters in a row, beside the results that have its letters in order. A name ranks higher when one of its words begins with a near miss of a word of five letters or more, which as a rule puts the name that was meant first, and a near miss that is only in a folder's name ranks lower, so `mian` lists `main.rs` ahead of everything in a folder named `Many`. A word that a result has as typed brings no near misses, a search whose words are all such lists what it listed before, and so does every search with **Allow typos** off. A search for letters with gaps, such as `pckg` for `package.json`, can now list a near miss such as `pkg-config` among its results, or ahead of them. `fff find` follows the same rules.

## [0.5.1] - 2026-11-09

This release keeps every folder on screen up to date with files other programs add, remove, or rename, including folders opened in place in the list and the column view's panes. The sidebar's tree also scrolls sideways when it's wider than the sidebar.

### Fixed

- When deep folders or long names made the sidebar's tree wider than the sidebar, names ran off its edge and could only be read in a tooltip. The tree now scrolls sideways, as Explorer's navigation pane does.
- Folders opened in place in the list view, and the column view's panes after the first, now show files that other programs add, remove, or rename. Only the folder the window showed was checked before, so a build script's output could stay out of sight until a refresh.
- A file created while fffinder read a folder could stay out of sight until something else in the folder changed. fffinder now notes the folder's change time before reading it, not after, so the next check catches the file.
- Checking folders for changes no longer runs on the window's thread, where a stalled network volume could freeze the window every two seconds.

## [0.5.0] - 2026-11-09

This release adds an explore mode to Quick Look for JSON, TOML, CSV, and other structured files. Copying and moving no longer delete anything, and Replace sends the old item to the Trash. On macOS, indexing waits for Full Disk Access instead of setting off a prompt per folder, and the sidebar runs edge to edge, as in macOS 27.

### Added

- Quick Look has an explore mode for structured files. Cmd+Space or File › Explore Data opens it. It shows what Nushell's `open` reads, one level at a time, the way Nushell's `explore` does: a record as its fields, a table as rows and columns, a list as its items. Click a nested value, or press Return on it, to go inside. The path above the grid shows where you are, and clicking a name in it or pressing Escape goes back. In Quick Look, Space and Cmd+Space switch between text and explore mode, and so do the Text and Explore buttons at the bottom. See [Exploring data](docs/manual.md#exploring-data).

### Changed

- The sidebar runs edge to edge, attached to the window, instead of floating inset from its edges. macOS 27 Golden Gate went back to this style, and the Windows and Linux file managers never left it.
- CSV, JSON, TOML, YAML, XML, INI, and the other structured text files preview as colored text in the gallery, the column view, the Preview Pane, and Quick Look. They used to show as a Nushell table whose nested values couldn't be opened. SQLite databases, spreadsheets, MessagePack, and binary plists still preview as a table. `nu-highlight` colors NUON files, as it does `.nu` scripts.
- Code previews use bat's grammars instead of syntect's own, which adds TOML, INI, CSV, TSV, and many other languages.
- Explore mode and the Nushell table previews load the plugins you registered with `plugin add`. With `nu_plugin_formats` registered, INI, email, calendar, vCard, and plist files open as data.
- When the Quick Look window is narrow, its buttons move to a second line instead of cutting off the file's name and details.
- A nested table in a Nushell table cell reads `[table 3 rows]`, as in Nushell, instead of `[list 3 items]`.

### Fixed

- On macOS without Full Disk Access, indexing set off a permission prompt for Desktop, then Documents, then Downloads, and on through the other protected folders, each one stealing the focus. fffinder now checks for access before it indexes anything. If access is off, indexing waits and one dialog explains why, and System Settings opens only from the dialog's button. Index Without It or Don't Ask Again goes ahead without access. Clicking "Indexing paused" in the sidebar footer brings the dialog back.
- Replace used to delete the old item for good. Now the old item goes to the Trash as "name (replaced).ext", and a replaced folder goes whole, with everything in it. A second Undo puts it back under its own name. If the Trash refuses it, as a network volume without one can, it stays beside the new item.
- Pasting or dropping same-named items from different folders keeps them all, and the later ones get numbered names like "name 2.ext". With Replace chosen, the second used to delete the first.
- When another item takes a name while a copy, move, rename, Compress, or Extract runs, fffinder no longer writes over it. It builds each copy under a hidden name and moves it into place with a rename that fails if the name is taken.
- Replace refuses two cases that used to lose data: a link replacing the file it points to, and a folder replaced while it holds other items in the same copy or move.
- A move to another volume flushes the copy to disk and checks its size before it removes the original.
- Copies keep extended attributes such as Finder tags and comments. Folders used to lose them, as did files of 32 MB or more copied to another volume, and every file copied on Linux.
- Copying a folder with a pipe in it reports the pipe instead of hanging.
- Renaming an item to the name of a broken link now fails instead of replacing the link, and New Folder skips a name a broken link holds.
- Undo and Redo wait for running copies and moves.
- On macOS, the journal that Put Back reads to find where items came from could lose entries when several jobs changed it at once.
- fffinder took a structured file whose data mentions SQLite for a database, so its preview failed with "Can't convert to database". Nushell's own `Cargo.toml`, with its `sqlite` feature, was one.

## [0.4.0] - 2026-11-08

This release adds a tree mode to the sidebar, which works the way Explorer's navigation pane does, and on macOS a check at startup for Full Disk Access.

### Added

- The sidebar has two modes, list and tree. List mode is the sidebar as it was. Tree mode shows folders as a tree, the way Explorer's navigation pane does. Choose with View > Sidebar as List and Sidebar as Tree, or with List and Tree in Settings > Sidebar, saved as `sidebar_mode`. Windows starts in tree mode, and macOS and Linux in list mode. Each Favorites and Locations row gets a triangle that opens it in place to show the folders inside, and those open the same way. Clicking a folder shows it in the window, and the tree opens down to whatever folder the window shows, which Settings > Sidebar can turn off.
- In tree mode, clicking a sidebar row gives it the keyboard. The arrows, Page Up and Down, Home and End, and typed letters move through it, Right and Left open and close folders, Return goes to the window's items, and F2, Cut, Copy, Paste, Delete, and Cmd+I act on the selected folder.
- Folders in the tree take dropped items, drag out like items in the window, and open after a moment when a drag waits over them. Their right-click menu has New Folder, Paste Into, Rename, Get Info, Move to Trash, and the rest of a folder's commands. Renaming, moving, or trashing the folder the window shows takes the window along, and Undo brings it back. Back and Forward follow a renamed or moved folder too.
- The tree reads a folder only when it opens, reading several at once in parallel. It shows a folder's triangle only when there are folders inside, and a lock on a folder it can't read. Every two seconds it reads again any open folder that changed, and looks again inside any folder without a triangle that changed. Closing a folder closes the folders open inside it, so what's out of sight isn't kept up to date.
- On macOS, fffinder checks for Full Disk Access when it starts. Without it, fffinder opens System Settings at Privacy & Security > Full Disk Access and says in a dialog what to turn on there: fffinder itself, or the terminal it was started from. Don't Ask Again turns the check off. Settings > Privacy shows what the check found, has a button to the System Settings pane, and turns the check back on. The Trash, when it can't be read for lack of Full Disk Access, has the same button.

## [0.3.0] - 2026-11-07

This release adds file manager basics that were missing: resizable columns, box selection, renaming in place, cut and paste, and windows that reopen where they were. Unless a line says otherwise, each feature works on macOS, Linux, and Windows. Shortcuts are written as on macOS; on Linux and Windows, Cmd is Ctrl.

### Changed

- Tabs and windows now share settings as they change: hidden files, Keep Folders on Top, columns and widths, the sidebar, favorites, Smart Folders, appearance, and text sizes. Each tab or pane keeps its own view, sort, groups, icon size, and search kind, and a new tab or window starts with the latest of those.
- Move to Trash no longer asks first, as in Finder and Explorer. Cmd+Z or Put Back restores the items. Delete Immediately and Empty Trash still ask, since neither can be undone.
- In the list view, only the Name column drags a file. The other columns draw a selection box, as in Finder and Explorer.
- On macOS, apps are no longer indexed. "This Computer" searches find them by reading `/Applications`, `/System/Applications`, `~/Applications`, and the folders directly inside them, so Calculator, Terminal, and the other apps in `/System/Applications` are found too. With the files inside app bundles out of the index, memory after indexing settled at 150 MB instead of 258 MB on the development Mac, and name searches took 25 to 35 ms instead of 65 to 100 ms. fffinder removes `/Applications` from existing search locations once. Add it back with Add Folder… to search inside bundles. Settings › Search locations has an Applications switch to stop finding apps.
- Apps in the app folders show their sizes in the list view. fffinder adds them up in the background the first time you open the folder.
- Run from a terminal without a folder, fffinder opens the folder you ran it from, on every system, as `--term` already did. Before, it opened the last folder. When fffinder is already running, that window goes to the folder instead of only coming forward. Started from the Dock, Finder, Explorer, or a desktop menu, it still opens the last folder.

### Added

#### Columns and text that doesn't fit

- You can resize every list column now, including Name and the Folder column in search results, by dragging the line at the edge of its header. Double-click the line to fit the column to its longest text. When columns are wider than the window, the list scrolls sideways.
- Text that's cut off shows in full in a tooltip when you rest the mouse on it: list cells and headers, names in the other views, sidebar rows, path bar crumbs, and tab titles. fffinder cuts file names and folder paths in the middle, so their ends stay visible.
- Drag the edge of the sidebar or of a column view pane to resize it. fffinder saves the width.
- Click the Folder header in search results and Recents to sort by folder.

#### Selecting and moving around

- Drag in empty space to select with a box in the icon and list views. In the list, drag from any column but Name. The view scrolls when the mouse goes past its edge, and Cmd or Shift adds to the selection.
- Page Up and Page Down move through the list, icon, and column views. Shift extends the selection with them and with Home and End.
- Move to Trash and Delete Immediately select the next item. Anything that couldn't go to the Trash stays selected, so you can try again.
- The status bar adds up the selected items: "2 of 12 selected (1.4 MB)".
- The back and forward buttons on a mouse go back and forward.
- Go to Folder lists the items that match from the moment it opens and as you type. Tab finishes the path, and clicking a match fills it in. Relative paths start from your home folder in places like Recents and the Trash.
- F5 refreshes outside split view, and Alt+Up goes to the enclosing folder. On Linux and Windows, Ctrl+L is Go to Folder, Alt+Enter is Get Info, and Shift+Delete is Delete Immediately.

#### Working with files

- Rename edits the name in place in the list, icon, and column views, with the part before the extension selected. Return or clicking elsewhere keeps it, and Escape cancels. Going to another app leaves the edit as it is. New Folder names the folder the same way. The gallery still asks in a dialog.
- Cmd+X cuts the selected items, and Cmd+V then moves them. They look faint until they're pasted. Escape cancels, and so does copying anything else, here or in another app. Edit › Cut and the item menu have it too.
- Hold dragged items over a folder, a sidebar place, or a path bar crumb for a moment and it opens, with the drag still going.
- Drop items on a path bar crumb to move them there, and right-click a crumb for its menu.

#### Windows, tabs, and the sidebar

- Windows reopen where they were, at the same size. fffinder saves the place even if you close the window or quit right after moving it. `--pick` windows open in the middle of the screen.
- A preview pane beside the list and icon views (Cmd+Shift+P, or View › Toggle Preview Pane). It follows the selection and resizes from its left edge.
- A folder opens in the view and sort last chosen in it, and a folder with none keeps the view you're in. Settings › Remember each folder's view turns this off.
- Open in New Tab and Open in New Window, in the menus of folders, sidebar rows, and path bar crumbs. Middle-click, Cmd+double-click on a folder, and Cmd+click on a sidebar row open a new tab too.
- Drag a Favorites row onto another to reorder them.
- The empty-space menu has Select All, View, and Sort By.

#### Indexing

- After a scan, fff-search reads each file once to flag binaries, which takes minutes for a large folder and keeps the CPU busy (issue #3). The sidebar footer says "Finishing index…" while that runs, and `GET /v1/status` reports it as `finishing`, for each location and overall.

### Fixed

- The search field ran off the right side of the window at larger text sizes and in narrow windows. The toolbar now measures the space it has and folds controls away as it runs out. The folder search button goes first, then the view buttons become one menu, then the Nushell and Sort menus move into the Actions menu.
- The Folder column in search results could shrink to half its width to make room for the other columns, which cut paths to a few characters. It keeps its width now, and Name shrinks instead, down to its smallest size.
- On disks that ignore case, as macOS and Windows disks do by default, renaming an item to change only the case of its name said the name was already taken.
- Dragging items showed their names in black, which was hard to read on the dark theme's gray. Drag previews now use the theme's text color and font.
- Icon view names cut off at two lines now end in an ellipsis.
- After a window changed size in one step, such as being zoomed, the icon view kept its old column count until the mouse next moved, which could leave items off the right edge.
- Settings could be lost. Each tab and window kept its own copy and saved all of it, so an older copy could write old values over newer ones, and so could a `--pick` or `--term` run. Now there's one copy, and each change writes only the fields it changed into the file. A change made just before quitting is saved too. If the settings file can't be read, for example because a hand edit left a typo, fffinder moves it to `settings.bad.json` instead of writing over it.
- On macOS, the Dock and the window switcher showed a generic executable icon when fffinder ran outside `fffinder.app`, as after `cargo install` or `scripts/install.nu`. fffinder now sets its icon itself. X11 windows get the icon too, and on Linux `scripts/install.nu` installs the desktop entry and icon, which Wayland needs.

## [0.2.0] - 2026-10-28

fffinder can now manage files as well as find them. Unless a line says otherwise, each feature works on macOS, Linux, and Windows. Shortcuts are written as on macOS; on Linux and Windows, Cmd is Ctrl. [The manual](https://github.com/fdncred/fffinder/blob/main/docs/manual.md) has the details.

### Added

#### Working with files

- Cmd+C copies the selected items, Cmd+V pastes them into the folder shown, and Cmd+Alt+V moves them there. On macOS and Windows the clipboard holds them as files, so Finder and Explorer can paste them, and files copied there paste into fffinder.
- Dragging items onto a folder, a column, or a sidebar place moves them. Holding Option on macOS, or Ctrl on Linux and Windows, when you let go copies them, and so does a drag that includes any item from another volume. Files dropped from other apps are copied in.
- When names clash, a dialog offers Stop, Skip, Keep Both, or Replace. Replace removes the old item only once its replacement is complete.
- Copies, moves, Compress, and Extract run in the background with a progress row and a Stop button. The work starts at once while fffinder counts the bytes alongside it, and the bar stays at 0% until the count is done. When a move to another volume copies an item but can't remove the original, a warning says so, and Undo treats the item as a copy.
- Cmd+Z undoes renames, batch renames, moves, copies, new items, and moves to the Trash, and Cmd+Shift+Z redoes them. One list of the last 100 operations covers every window. When an Undo can't finish, what it reversed stays reversed and Cmd+Z tries the rest again. Undo never overwrites an item that has taken an old name since.
- A Trash row at the end of the sidebar lists what's in the Trash, with Put Back, Delete Immediately, and Empty Trash.
- Get Info (Cmd+I) shows an item's kind, size and size on disk, dates, link target, default app, owner, group, and the address a download came from. Clicking a permission box changes the item's permissions, and a folder's size is added up in the background.
- Open With in the item menu lists the apps that open the file's type. Always Open With makes the chosen app the default.
- Duplicate (Cmd+D) copies items beside themselves as "name copy", and New File (Cmd+Alt+N) makes an empty file.
- Make Alias makes Finder aliases on macOS and Create Shortcut makes shortcuts on Windows. Make Symbolic Link works everywhere.
- Compress puts the selection in a zip. Extract unpacks zip, tar, and tar.gz archives, and opening an archive extracts it.

#### Browsing

- Tabs. Cmd+T opens one, Ctrl+Tab and Cmd+Shift+] and [ move between them, and Cmd+W closes one. Drag a tab onto another to reorder them. Right-click a tab, or use Window > Move Tab to New Window, to give it a window of its own.
- Split View (Cmd+Backslash) adds a second pane beside the current tab. F5 copies the selection into the other pane's folder, and F6 moves it there.
- The list view opens folders in place with disclosure triangles. Right-click the header to choose columns from Date Modified, Date Created, Date Last Opened, Size, Kind, Permissions, and Git. Columns can be dragged to reorder or resize them, and the layout is saved.
- Calculate All Sizes shows folder sizes from the search index without reading the disk. The Git column shows each file's git status.
- Keep Folders on Top sorts folders first in every view.
- Group By shows the list and icon views in groups by name, kind, date, or size, like Finder's Use Groups. Click a group's header to collapse it.
- Removable disks, disk images, and servers in the sidebar have an eject button. The status bar shows the free space on the current folder's volume.
- Connect to Server (Cmd+K) mounts SMB and WebDAV servers, AFP, NFS, and FTP on macOS and Linux, and SFTP on Linux. It remembers them under Recent servers, leaving out any password typed in the address.

#### Previews

- Quick Look opens in a window of its own that you can move, resize, maximize, or make full screen. The arrow keys still step through items. In `--term` mode Quick Look is still a dialog, because the terminal shows one window.
- PDFs read as in a PDF viewer, in the gallery and in Quick Look. Pages scroll in one column and open fitted to the width. The toolbar has previous and next page buttons, "Page 2 of 12", zoom buttons, and a zoom menu with Fit Width, Fit Page, Actual Size, and sizes from 25% to 400%. Pinching, Cmd+scroll, Cmd+Plus, Cmd+Minus, Cmd+0, Page Up, and Page Down work too. [hayro](https://github.com/LaurenzV/hayro) draws the pages, so they look the same on every system.
- Code is colored with syntect, in a light or dark theme to match the window.
- Markdown is rendered.
- Zip and tar archives show a table of what's inside.
- Fonts show their alphabet and a sample line drawn in the font.
- MP4, MOV, M4A, M4V, WAV, and FLAC files show their running time.
- PDFs, videos, documents, fonts, and images show the system's thumbnails in the icon view, the gallery strip, and previews. They come from QuickLook on macOS, the shell's thumbnail handlers on Windows, and freedesktop.org thumbnailers on Linux, and are cached in the data folder, up to 256 MB, dropping the least recently used first.

#### Terminal mode

- `fffinder --term` works on Windows, with a build that has the `term` feature. Frames go out as kitty graphics in terminals that have them, such as WezTerm, Rio, and VS Code's terminal, and as sixel images, sending only the cells that changed, in Windows Terminal 1.22 or later.

#### Releases

- Release archives and shell and PowerShell installers for macOS, Linux, and Windows on x86_64 and ARM64, built with dist. Each archive includes the `fff` Nushell module.
- `cargo binstall --git https://github.com/fdncred/fffinder fffinder` installs the release binary for your system instead of building it.

### Changed

- A search made before the index is ready now shows results within 25 ms of a location finishing indexing. It used to retry every 600 ms. The index is rebuilt at every launch, so a search right after launch can still wait a few seconds.
- While an Undo or Redo runs, other file operations wait and say "Wait for Undo to finish".
- Updated GPUI Kit to 0.8.1, and every other dependency to its latest version.
- On macOS, Move to Trash no longer asks for permission to control Finder. fffinder moves items to the Trash itself, as most Mac apps do, so Finder's Put Back doesn't work for them; Put Back in fffinder's Trash view and Undo do.
- The sidebar's Locations load in the background, so a slow or offline drive no longer holds up opening a window. On Windows, fffinder lists drives from the system's own table and asks only local and removable ones for a name, so a mapped drive whose server is offline no longer stalls it.

### Fixed

- `fff files` without a query listed each file added since the index was built twice.

### Known limitations

- On Linux, GPUI can only put text on the clipboard, so files copied in fffinder paste as files only into fffinder.
- Dragging files out to other apps works on macOS and Wayland. GPUI doesn't support it on Windows or X11.
- On macOS, fffinder can put back only items it moved to the Trash, and Finder's own Put Back doesn't work for those.
- On Windows, `fffinder --term` clicks land on whole cells and emoji are one color. In Windows Terminal, which gets sixel images, frames are drawn at 10 by 20 pixels a character cell, so text looks softer than with kitty graphics, and images have at most 256 colors.
- Connect to Server can't mount SFTP on macOS. On Linux it can't ask for a password, so put the user name in the address and keep the password in your keyring.
